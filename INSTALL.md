# Personal Assistant — Windows Installation

This guide installs the local-first Personal Assistant on a Windows x64
computer. Conversations, memories, language-model inference, speech recognition,
and spoken replies run locally.

## 1. System requirements

- Windows 10 or Windows 11, x64
- A reasonably modern 64-bit Intel or AMD processor
- 8 GB RAM minimum; 16 GB recommended
- Approximately 4 GB free disk space
- A microphone and speakers or headphones
- Java 21
- Maven 3.9 or newer only when building from source
- Internet access for the initial source build or Git LFS download

Windows ARM is not currently supported.

## 2. Install Java 21

Check the installed Java version:

```powershell
java -version
```

The output must report Java 21. If Java is missing, install a Java 21 JDK such
as Amazon Corretto, Eclipse Temurin, or Microsoft Build of OpenJDK. Close and
reopen PowerShell after installation, then run `java -version` again.

## 3. Option A: Run the portable package

Copy the entire `PersonalAssistant` directory to the target computer. Do not
copy only `personal-assistant.jar`.

The directory must contain:

```text
PersonalAssistant/
├── personal-assistant.jar
├── config/
├── data/
├── logs/
├── models/
│   ├── language/
│   ├── speech-to-text/
│   └── text-to-speech/
├── native/
│   └── windows-x64/
└── skills/
```

Open PowerShell in that directory and run:

```powershell
java -jar personal-assistant.jar
```

The first generated response can take longer because the local language model
must be loaded into memory.

## 4. Option B: Build from source

### 4.1 Install Maven and Git LFS

Verify Maven:

```powershell
mvn -version
```

Verify Git LFS:

```powershell
git lfs version
```

If Git LFS was just installed, initialize it:

```powershell
git lfs install
```

### 4.2 Clone and download models

```powershell
git clone <repository-url>
cd <repository-folder>
git lfs pull
```

Confirm that the model files are real binary files rather than small Git LFS
pointer files. The language model is approximately 1.23 GB:

```powershell
Get-Item portable\models\language\qwen2.5-1.5b-instruct-q5_k_m.gguf |
Select-Object Name, Length
```

### 4.3 Build

```powershell
mvn clean package
```

Maven may appear to pause at:

```text
Copying resources from portable to target\PersonalAssistant
```

This is normal. It is copying more than 1 GB of local models. Wait for:

```text
BUILD SUCCESS
```

### 4.4 Run

```powershell
cd target\PersonalAssistant
java -jar personal-assistant.jar
```

## 5. Enable microphone access

Before using voice input:

1. Open **Settings → Privacy & security → Microphone**.
2. Enable **Microphone access**.
3. Enable **Let desktop apps access your microphone**.
4. Open **Settings → System → Sound → Input**.
5. Select the desired microphone as the Windows default input device.
6. Confirm that its input-level meter moves when you speak.

The assistant uses the current Windows default recording device. It does not
require a particular microphone brand.

## 6. Using the assistant

- Type a message and select **Send** for text chat.
- Select **Talk** to begin recording.
- Speak, then select **Stop**.
- Whisper transcribes the recording locally and submits the text.
- Keep **Speak replies** selected to hear responses generated by Piper.

No conversation is sent to OpenAI. Cloud access is disabled by default.

## 7. Local data and backups

User data is stored below the application directory:

```text
data/
config/
skills/
```

Close the application before backing up or replacing these directories. Copy
them to a secure location to preserve conversations, memories, settings, and
installed skills.

Do not commit personal database files to a shared source repository.

## 8. Updating

For a source checkout:

```powershell
git pull
git lfs pull
mvn clean package
```

Close the running assistant before rebuilding because Windows locks the active
JAR file.

To update only the application while preserving personal data, back up the
existing `data`, `config`, and `skills` directories before replacing the
portable package.

## 9. Troubleshooting

### Local model files are missing

Confirm these files exist:

```powershell
Get-Item models\language\*.gguf
Get-Item native\windows-x64\llama-server.exe
```

For a source checkout, run `git lfs pull` and rebuild.

### Microphone cannot be opened

- Confirm Windows microphone and desktop-app access are enabled.
- Select a Windows default input device.
- Test the device with Windows Sound Recorder.
- Close voice-processing applications temporarily if they hold the device.
- Restart Windows after changing system-wide microphone permissions.

### Speech transcription fails

Inspect:

```powershell
Get-Content logs\whisper.log -Tail 100
```

### Spoken replies fail

Inspect:

```powershell
Get-Content logs\piper.log -Tail 100
```

Confirm that a Windows default playback device is selected.

### Language-model startup or reply fails

Inspect:

```powershell
Get-Content logs\llama-server.log -Tail 100
```

The first reply may take 30–90 seconds on slower processors.

### Maven cannot replace the JAR

Close the Personal Assistant window and run:

```powershell
mvn clean package
```

## 11. Secure mobile access over the local network

The camera API requires a trusted HTTPS connection on mobile browsers. The
portable package can create a private certificate authority used only by your
home installation.

### 11.1 Create the certificates

On the PC, run `ipconfig` and find the IPv4 address of the active Wi-Fi adapter.
Then open Command Prompt in the packaged `PersonalAssistant` directory:

```cmd
setup-https.cmd 192.168.1.25
```

Replace the example address with the PC's actual address. If the router later
assigns the PC a different address, reserve the address in the router or run
the setup script again using the new address.

The script creates:

```text
config\https.p12
config\local-ca.p12
config\https.properties
config\personal-assistant-ca.cer
```

Keep the `.p12` and `.properties` files private. Never commit or share them.
The setup command also prints a generated household access PIN. The username
is `home`.

### 11.2 Trust the certificate on Android

Copy `config\personal-assistant-ca.cer` to the phone. The exact menu varies by
manufacturer, but it is normally under:

```text
Settings > Security > Encryption & credentials > Install a certificate > CA certificate
```

Select the copied certificate and acknowledge that it is a private local CA.
Use this only on a phone you control.

### 11.3 Trust the certificate on iPhone or iPad

Send `personal-assistant-ca.cer` to the device and open it to install the
profile. Then open:

```text
Settings > General > About > Certificate Trust Settings
```

Enable full trust for `Personal Assistant Local CA`.

### 11.4 Start and connect

Start secure LAN mode:

```cmd
run-https.cmd
```

Or double-click `run-https.cmd`. Keep its terminal window open. On the phone,
while connected to the same private Wi-Fi, open:

```text
https://192.168.1.25:8787
```

When the browser requests credentials, use username `home` and the six-digit
PIN printed by `setup-https.cmd` or `run-https.cmd`. The browser normally
remembers the login until it is completely closed. Allow camera permission
when prompted.

If Windows Firewall blocks the connection, allow Java on **Private networks**
or run this once from an Administrator Command Prompt:

```cmd
netsh advfirewall firewall add rule name="Personal Assistant HTTPS" dir=in action=allow protocol=TCP localport=8787 profile=private
```

The current PIN is stored locally in `config\https.properties`. To reset it,
run `setup-https.cmd` again with the current LAN IP, reinstall the newly
generated CA certificate on the phone, and restart the application.

Do not use HTTPS LAN mode on public, office, hotel, or guest Wi-Fi, and do not
forward port 8787 through the router.

Exact model/runtime download locations and license information are documented
in:

- `docs/LOCAL_MODEL.md`
- `docs/LOCAL_VOICE.md`
